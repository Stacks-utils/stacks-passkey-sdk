## What this SDK does

The Stacks Passkey SDK lets **web apps** onboard users without a browser wallet extension or seed phrase:

- Users create a **smart account** on Stacks using Face ID, Touch ID, or Windows Hello
- Transactions are authorized with **WebAuthn** and verified on-chain with Clarity 5 **`secp256r1-verify`**
- Gas can be **sponsored by your relay** (gasless) or **paid from the smart account's STX** (account-pay)

Your app talks to three pieces:

| Piece | Role |
|-------|------|
| **`@stacks-passkey/core`** | WebAuthn, session, tx building, relay client |
| **`@stacks-passkey/relay`** | Self-hosted server that pays network fees |
| **`passkey-account.clar`** | On-chain smart account — transfers, key management, `execute-via-adapter` |
| **`passkey-adapter.clar`** | Universal registry — forwards to app contracts implementing `passkey-exec-trait` |

Passkey private keys **never leave the device**. The relay cannot forge signatures — it only sponsors gas.

---

## Who should use it

**Good fit:**

- Consumer dApps that want Web2-style onboarding on Stacks
- Apps where users shouldn't manage seed phrases
- Projects willing to run (or use) a gas sponsorship relay

**Not a fit (yet):**

- Server-side / CLI-only apps (WebAuthn requires a browser)
- Mainnet before Clarity 5 / Epoch 3.4 is live on your target network

## How it works on Stacks

```
User taps "Sign up"
       │
       ▼
WebAuthn creates P-256 keypair in secure enclave
       │
       ▼
SDK submits register(public-key) ──► passkey-account.clar
       │                              (stores authorized key)
       ▼
User taps "Transfer"
       │
       ▼
SDK fetches action hash from contract (read-only call)
       │
       ▼
WebAuthn signs hash (biometric prompt)
       │
       ▼
SDK builds sponsored contract-call tx
       │
       ▼
Relay co-signs as fee payer ──► Stacks network
       │
       ▼
Contract verifies secp256r1 signature ──► executes transfer
```

**Two keys are involved:**

1. **Passkey (P-256)** — proves the user authorized the action. Stored in the device enclave.
2. **Origin key (secp256k1)** — signs the outer Stacks transaction envelope. Generated by the SDK and stored in `localStorage`. Not secret in the same sense; it cannot bypass passkey authorization on-chain.

## Step 1 — Deploy contracts

The SDK expects **`passkey-account.clar`** and **`passkey-adapter.clar`**. App contracts implement `passkey-exec-trait` from the adapter. This repo includes contracts and Clarinet tests.

```bash
cd contracts
clarinet check -d
npm run test

# Deploy adapter + account + demo app to testnet
clarinet deployments apply -p deployments/default.testnet-plan.yaml
```

After deployment, note:

- **Account** — `STxxx.passkey-account`
- **Adapter** — `STxxx.passkey-adapter` (set `PASSKEY_ADAPTER_ADDRESS` on relay)

Shared testnet IDs are in `config/testnet.json`.

### App contract setup

1. Implement `passkey-exec-trait` from `passkey-adapter` (see `passkey-demo-app.clar`).
2. Register via relay: `spk ensure STxxx.my-app` or `client.invoke()` (auto-ensure).
3. Users call through `execute-via-adapter` on the shared passkey account.

## Step 2 — Run the relay

The relay is a self-hosted server that sponsors transaction fees. Without it, users would need STX in a separate wallet to pay gas.

```bash
cp packages/relay/.env.example packages/relay/.env
```

Edit `packages/relay/.env`:

```env
PORT=8787
HOST=127.0.0.1
STACKS_NETWORK=testnet
RELAY_ADMIN_API_KEY=your-long-admin-secret
SPONSOR_PRIVATE_KEY_FILE=./sponsor.key
GAS_TANK_PATH=./data/gas-tank.json
BOOTSTRAP_DEMO_PROJECT=true
ALLOWED_CONTRACTS=ST3XHHZ1CXVCNYXK3FQ1FDGJ9NK6YBJBJK3FVY5KQ
MAX_FEE_MICRO_STX=100000
```

Generate a sponsor key (dedicated hot wallet — **not** your contract deployer):

```bash
chmod +x scripts/setup-relay-key.sh
./scripts/setup-relay-key.sh
```

Fund the sponsor address with testnet STX, then start:

```bash
npm run dev:relay
```

Verify:

```bash
curl http://localhost:8787/health
# {"ok":true,"sponsorAddress":"ST...","network":"testnet"}
```

See [packages/relay/SECURITY.md](../packages/relay/SECURITY.md) for production hardening.

## Step 3 — Create an API key

Each app/project gets an API key (`spk_...`) tied to a **gas tank** balance.

**Option A — Bootstrap (dev):** With `BOOTSTRAP_DEMO_PROJECT=true`, the relay logs a key on first start. Check `packages/relay/data/gas-tank.json`.

**Option B — Admin dashboard:**

```bash
npm run dev:admin   # http://localhost:3001
```

Connect the relay sponsor wallet, create a project, copy the API key.

**Option C — Admin API:**

```bash
curl -X POST http://localhost:8787/v1/admin/projects \
  -H "Content-Type: application/json" \
  -H "X-Admin-Key: your-admin-secret" \
  -d '{"name":"My App","initialGasMicroStx":"5000000"}'
```

Store the returned `apiKey` securely. Each gasless sponsorship debits up to `MAX_FEE_MICRO_STX` from the project's tank.

## Step 5 — Configure PasskeyClient

Create one client instance per app (or use `PasskeyProvider` in React):

```typescript
import { PasskeyClient } from '@stacks-passkey/core';
import { STACKS_TESTNET } from '@stacks/network';

export const passkeyClient = new PasskeyClient({
  // Stacks network
  network: STACKS_TESTNET,

  // Factory mode (default) — relay deploys per-user passkey-acc-* on sign-up
  deployerAddress: 'ST3XHHZ1CXVCNYXK3FQ1FDGJ9NK6YBJBJK3FVY5KQ',
  factoryName: 'passkey-factory',

  // WebAuthn relying party — MUST match your domain in production
  rpId: typeof window !== 'undefined' ? window.location.hostname : 'localhost',
  rpName: 'My Stacks App',
  origin: typeof window !== 'undefined' ? window.location.origin : 'http://localhost:3000',

  // Relay — hosted testnet default; use http://localhost:8787 for local relay
  relayUrl: 'https://stacks-passkey-relay.onrender.com',
  relayApiKey: 'spk_your_project_key_here',

  // Fee configuration
  fee: {
    mode: 'gasless',
    relayUrl: 'https://stacks-passkey-relay.onrender.com',
    relayApiKey: 'spk_your_project_key_here',
  },
});
```

### Configuration fields explained

| Field | Required | Description |
|-------|----------|-------------|
| `network` | Yes | `STACKS_TESTNET` or `STACKS_MAINNET` from `@stacks/network` |
| `deployerAddress` | Yes* | Deployer for factory, adapter, and per-user accounts |
| `factoryName` | No | Factory contract name (default `passkey-factory`) |
| `useFactory` | No | Default `true`; legacy shared account when `false` + `contractName` |
| `contractAddress` | Legacy | Shared account address when `useFactory: false` |
| `contractName` | Legacy | Shared account name when `useFactory: false` |
| `rpId` | Yes | WebAuthn relying party ID — your domain without protocol/port |
| `rpName` | Yes | Human-readable name shown in passkey prompts |
| `origin` | Yes | Full origin URL (`https://app.example.com`) |
| `relayUrl` | Yes | Your relay server URL |
| `relayApiKey` | Yes* | Project API key (`spk_...`). *Required for gasless |
| `fee.mode` | Yes | `'gasless'` or `'account-pay'` |
| `fee.maxFeeMicroStx` | No | Max fee for account-pay (default `100_000n`) |
| `fee.feeRecipient` | No | Relayer address for account-pay (auto-fetched from `/health`) |

### WebAuthn domain rules

| Environment | `rpId` | `origin` |
|-------------|--------|----------|
| Local dev | `localhost` | `http://localhost:3000` |
| Production | `app.example.com` | `https://app.example.com` |
| Subdomain | `app.example.com` | `https://app.example.com` |

`rpId` must be a registrable domain suffix of the current host. `localhost` is special-cased for dev.

## Step 6 — Register a user

Registration creates a WebAuthn passkey, stores a session, and submits the public key on-chain.

```typescript
async function signUp(userId: string, displayName: string) {
  const credential = await passkeyClient.register(userId, displayName);

  console.log('Credential ID:', credential.credentialId);
  console.log('Public key (hex):', Buffer.from(credential.publicKey).toString('hex'));
  console.log('Registration txid:', credential.txid);

  // credential.txid === 'already-registered' if key was already on-chain
  return credential;
}
```

**What happens internally:**

1. Browser WebAuthn `credentials.create()` — user sees biometric prompt
2. SDK extracts P-256 public key from attestation
3. Session saved to `localStorage` (`stacks-passkey-session`)
4. Credential indexed for future sign-in
5. SDK calls contract `register(public-key)` via relay (gasless)
6. SDK waits for on-chain confirmation

**UI tips:**

- Call `register()` from a user gesture (button click) — required by some browsers
- Show loading state during on-chain confirmation (~10–30s on testnet)
- Use a stable `userId` (UUID) — not necessarily the user's email

## Step 7 — Sign in a returning user

Sign-in re-authenticates with a passkey already stored on the device:

```typescript
async function signIn() {
  const session = await passkeyClient.signIn();

  console.log('Signed in as:', session.publicKeyHex);
  console.log('Credential:', session.credentialId);

  return session;
}
```

**Requirements:**

- User must have registered on **this device** before (credentials in `localStorage`)
- Passkey must still be authorized on-chain (`is-key-authorized`)

**Errors you may see:**

| Error | Cause |
|-------|-------|
| `No passkeys found for this app` | No local credentials — user needs to sign up |
| `Passkey not recognized for this app` | Credential ID mismatch |
| `Passkey is not registered on chain` | Key was removed on-chain or wrong contract |

**Logout** clears the session but keeps credentials for sign-in:

```typescript
passkeyClient.logout();
```

## Step 8 — Execute actions

All state-changing operations go through `executeAction()`. The user approves each action with a biometric prompt.

### Transfer STX

Send STX from the smart account contract balance:

```typescript
import { hexToBytes } from '@stacks/common';

async function transferStx(session: PasskeySession, recipient: string, amountMicroStx: bigint) {
  const publicKey = hexToBytes(session.publicKeyHex);

  const txid = await passkeyClient.executeAction(
    { type: 'transfer', recipient, amount: amountMicroStx },
    publicKey,
    session.credentialId
  );

  console.log('Transfer txid:', txid);
  return txid;
}

// Transfer 1 STX (1_000_000 micro-STX)
await transferStx(session, 'ST1PHCPAAFW8ZFB9MNR87K97K5QXR3K1JSC01CY7Z', 1_000_000n);
```

**Before transferring:** Fund the smart account contract:

```
ST3XHHZ1CXVCNYXK3FQ1FDGJ9NK6YBJBJK3FVY5KQ.passkey-account
```

Send testnet STX to this contract principal. The contract holds STX collectively; each registered passkey can authorize transfers.

### Add a device key

Authorize another passkey (e.g. user's phone after registering on laptop):

```typescript
await passkeyClient.executeAction(
  { type: 'add-key', newPublicKey: anotherDevicePublicKeyBytes },
  hexToBytes(session.publicKeyHex),
  session.credentialId
);
```

### Remove a device key

Revoke a previously authorized key:

```typescript
await passkeyClient.executeAction(
  { type: 'remove-key', targetPublicKey: keyToRemoveBytes },
  hexToBytes(session.publicKeyHex),
  session.credentialId
);
```

### Factory smart accounts (default)

In factory mode (default when `deployerAddress` is set without `useFactory: false`), `register()` calls relay **`POST /v1/accounts/ensure`** with the user's pubkey. The relay:

1. Derives contract name `passkey-acc-{sha256(pubkey)[0:8]}`
2. Deploys `passkey-account.clar` if not present
3. Calls `register(pubkey)` on the instance
4. Calls `register-account(pubkey, account)` on `passkey-factory`

The session stores the user's **`contractId`** (e.g. `STxxx.passkey-acc-a1b2c3d4`). Fund that address for transfers.

```typescript
await client.register(crypto.randomUUID(), 'Alice');
console.log(client.getAccountContractId()); // STxxx.passkey-acc-...
```

Legacy shared-account mode: set `useFactory: false` and provide `contractAddress` + `contractName`.

### Invoke app contracts (adapter + catalog)

Use **`client.invoke()`** to call your app's contract functions. The relay catalog auto-registers contracts that implement `passkey-exec` on-chain via `passkey-adapter`.

**On your app contract**, implement the trait from the adapter:

```clarity
(impl-trait .passkey-adapter.passkey-exec-trait)

(define-public (passkey-exec
    (function-name (string-ascii 128))
    (arg0 uint) (arg1 uint) (arg2 principal) (arg3 principal) (arg4 (buff 1024))
  )
  (asserts! (is-eq function-name "set-score") (err u9001))
  ;; dispatch to internal logic using arg0, arg2, ...
  (ok u1)
)
```

**CLI / relay registration:**

```bash
export SPK_RELAY_URL=http://localhost:8787
export SPK_RELAY_API_KEY=spk_...
spk ensure STxxx.my-app
```

**SDK usage:**

```typescript
// invoke() calls relay ensure, then execute-via-adapter on passkey-account
const txid = await passkeyClient.invoke('STxxx.my-app', 'set-score', {
  arg0: 100n,
  arg2: userPrincipal,
});

// Or lower-level:
import { createInvokeAction } from '@stacks-passkey/core';

const action = createInvokeAction('STxxx.my-app', 'set-score', { arg0: 100n, arg2: userPrincipal });
await passkeyClient.executeAction(action, hexToBytes(session.publicKeyHex), session.credentialId);
```

| Arg slot | Type | Typical use |
|----------|------|-------------|
| `arg0`, `arg1` | `uint` | amounts, ids, flags |
| `arg2`, `arg3` | `principal` | recipients, accounts |
| `arg4` | `(buff 1024)` | serialized payload |

**Flow:** `passkey-account.execute-via-adapter` → `passkey-adapter.forward-invoke` → `your-app.passkey-exec`.

See `examples/demo/contracts/passkey-demo-app.clar` for a working example.

### Poll transaction status

The SDK returns a txid immediately. Confirm on-chain via Hiro API:

```typescript
import { normalizeTxId } from '@stacks-passkey/core';

async function waitForTx(txid: string, network = STACKS_TESTNET): Promise<string> {
  const id = normalizeTxId(txid);
  for (let i = 0; i < 45; i++) {
    const res = await fetch(`${network.client.baseUrl}/extended/v1/tx/${id}`);
    if (res.ok) {
      const { tx_status } = await res.json();
      if (tx_status === 'success') return tx_status;
      if (tx_status === 'abort_by_response' || tx_status === 'failed') {
        throw new Error(`Transaction failed: ${tx_status}`);
      }
    }
    await new Promise((r) => setTimeout(r, 2000));
  }
  throw new Error('Transaction not confirmed in time');
}
```

## Fee modes

### Gasless (recommended for onboarding)

Your relay pays gas. Cost is debited from the project's gas tank.

```typescript
fee: {
  mode: 'gasless',
  relayUrl: 'https://relay.yourapp.com',
  relayApiKey: 'spk_...',
}
```

- Users need **zero STX** for gas
- You maintain gas tank balance via admin dashboard
- Each tx debits up to `MAX_FEE_MICRO_STX` (default 100,000 µSTX = 0.1 STX)

### Account-pay

Relay sponsors upfront; smart account reimburses relayer on-chain.

```typescript
fee: {
  mode: 'account-pay',
  relayUrl: 'https://relay.yourapp.com',
  relayApiKey: 'spk_...',
  maxFeeMicroStx: 100_000n,
}
```

- Smart account must hold STX for transfer + fee reimbursement
- Uses `transfer-stx-with-fee` instead of `transfer-stx`
- `feeRecipient` auto-resolved from relay `/health` → `sponsorAddress`
- Gas tank is **not** debited (billing mode `account-pay`)

### Switching fee mode at runtime

```typescript
passkeyClient.setFeeConfig({
  mode: 'account-pay',
  relayUrl: 'http://localhost:8787',
  relayApiKey: 'spk_...',
  maxFeeMicroStx: 100_000n,
});
```

**Note:** Registration always uses gasless, even in account-pay mode.

## Next.js / SSR notes

The SDK uses browser APIs (`navigator.credentials`, `localStorage`). **Only import and use it on the client:**

```tsx
'use client';

import { PasskeyProvider, usePasskeyAccount } from '@stacks-passkey/react';
```

For Next.js App Router:

- Wrap passkey UI in a client component
- Pass `rpId` and `origin` from `window.location` inside `useEffect` or use env vars for production domain
- Do not instantiate `PasskeyClient` in Server Components or API routes for user-facing WebAuthn

You **can** use API routes to proxy relay `/sponsor` calls (recommended for production).

## Production: proxy relay API keys

**Never ship `spk_...` keys in public frontend bundles.** Anyone can extract them and drain your gas tank.

### Recommended pattern

```
Browser ──► Your API (/api/sponsor) ──► Relay (/sponsor)
              adds Authorization header
```

Example Next.js API route:

```typescript
// app/api/sponsor/route.ts
export async function POST(req: Request) {
  const { txHex, billingMode, estimatedFeeMicroStx } = await req.json();

  const res = await fetch(`${process.env.RELAY_URL}/sponsor`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${process.env.RELAY_API_KEY}`,
    },
    body: JSON.stringify({ txHex, billingMode, estimatedFeeMicroStx }),
  });

  return Response.json(await res.json(), { status: res.status });
}
```

Then implement a custom `RelayClient` wrapper or extend the SDK relay URL to point at your proxy. The SDK's `RelayClient` accepts any URL — point `relayUrl` at your backend proxy instead of the relay directly.

For local dev / demos, embedding the key in `.env` (`VITE_RELAY_API_KEY`) is acceptable.

## Multi-device key management

Each user can have multiple authorized passkeys:

1. User registers on Device A → key A on-chain
2. On Device B, user registers separately → key B on-chain (separate WebAuthn credential)
3. Or: on Device A, call `add-key` with Device B's public key

Sign-in always uses **local** credentials. A user who registered on their phone cannot sign in on their laptop unless they also registered or added a key there.

## Production deployment

1. **Deploy contracts** to mainnet (Clarity 5+ confirmed on network): `passkey-adapter`, `passkey-account`, your app with `passkey-exec`.
2. **Allowlist app contracts** on v4 via `set-contract-allowed`.
3. **Deploy relay** behind TLS reverse proxy (nginx, Cloudflare, etc.).
4. **Use `SPONSOR_PRIVATE_KEY_FILE`** with restrictive permissions — never inline keys.
5. **Set `ALLOWED_CONTRACTS`** to your deployer address only.
6. **Create per-environment API keys** (staging vs production).
7. **Proxy `/sponsor`** through your backend — do not expose `spk_...` in frontend.
8. **Set `rpId`** to your production domain.
9. **Serve app over HTTPS.**
10. **Monitor gas tank** balance; set up alerts before it runs dry.
11. **Fund sponsor wallet** with minimal STX needed for burst traffic.

## Security

| Topic | Guidance |
|-------|----------|
| Passkey keys | Non-custodial — stay in device enclave |
| Relay sponsor key | Hot wallet — minimal funds, rotate if exposed |
| API keys (`spk_...`) | Secrets — backend proxy in production |
| Admin key | Protect `RELAY_ADMIN_API_KEY`; admin UI requires wallet gate |
| Contract allowlist | Restrict relay to your deployer address (`ALLOWED_CONTRACTS`). v4 also allowlists call targets on-chain via `set-contract-allowed`. |
| WebAuthn rpId | Must match production domain |
| Origin key | Local to browser — clearing site data requires re-registration flow |

## Troubleshooting

| Symptom | Solution |
|---------|----------|
| `(err u1001)` unauthorized | Wrong WebAuthn payload or action hash mismatch. Use SDK latest + contract v3/v4. |
| `(err u1007)` replay | Platform passkey sign count 0. Use `passkey-account-v3` or v4 (both support counterless keys). |
| `(err u1010)` contract not allowed | Target not allowlisted on v4. Call `set-contract-allowed` as admin. |
| `BadNonce` | Transient — SDK retries. Don't clear localStorage mid-session. |
| `Contract not allowlisted` | Add deployer to relay `ALLOWED_CONTRACTS`. |
| `Insufficient gas tank balance` | Refill via admin dashboard. |
| `No passkeys found` | User must sign up on this device first. |
| Transfer fails, 0 balance | Fund smart account contract with STX. |
| WebAuthn not available | Use HTTPS or localhost. |
| Tx "not found" immediately | Testnet indexing takes 30–90s — poll Hiro API. |
| Account-pay fails | Ensure contract STX ≥ transfer + `maxFeeMicroStx`. |

## FAQ

**Q: Do users get their own contract address?**
A: No. All users share one passkey-account contract instance. Each user registers a unique public key on that contract. The contract holds STX in a shared balance.

**Q: Can users call any Clarity contract?**
A: Yes — if your contract implements `passkey-exec` and is registered on `passkey-adapter` via the relay catalog. Use `client.invoke()` from the SDK.

**Q: Does this replace Leather / Xverse?**
A: No. It's an alternative onboarding path for apps that want passkey UX. Users don't need an extension.

**Q: Can I use this on mainnet?**
A: Yes, once Clarity 5 is live on mainnet. Deploy your own contracts and relay.

**Q: What happens if a user clears browser data?**
A: Session and credentials are lost. User must sign up again (new passkey) and register on-chain. Use `add-key` beforehand for backup devices.

**Q: Is the origin key a security risk?**
A: The origin key only signs the tx envelope. On-chain authorization requires a valid WebAuthn proof from a registered passkey. The origin key alone cannot move funds.

**Q: How much STX should I fund the gas tank?**
A: Each gasless tx costs up to `MAX_FEE_MICRO_STX` (default 0.1 STX). Estimate: `daily_active_users × txs_per_user × 0.1 STX`.

**Q: Can one API key serve multiple apps?**
A: Yes, but use separate projects/keys per app for accounting and rate isolation.
